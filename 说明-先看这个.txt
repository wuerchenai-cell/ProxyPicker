ProxyPicker · 看这一页就够了
======================================================================

它是什么
--------
一个绿色小工具（单个 exe，1,044,504 字节，约 1020 KB，带图标），用来决定「哪些软件走代理、哪些直连」。

比如你平时挂梯子，但微信、QQ、游戏也想直连（省流量、不卡），
以前只能全局切来切去。装上它就能给每个软件单独一个开关。


必须先满足的前提（不满足就用不了）
----------------------------------
1. 电脑上已经在用 Clash Verge（或 Clash Nyanpasu / Mihomo Party / FlClash）。
   这个工具自己不带代理，它只是「分配谁走代理」，梯子还得你自己有。

2. 强烈建议开着「TUN 模式」（Clash Verge 里那个虚拟网卡开关）。
   为什么：这个工具的原理是「让内核按进程名给流量分配出口」，
   内核得先看得见这条流量才管得着。TUN 在网卡层接住全部流量，谁都跑不掉。
   不开 TUN 只能用系统代理，那只对「愿意读系统代理」的软件有效
   （浏览器、IDM 这类），微信、QQ、游戏、Antigravity 这类程序根本不读，
   它们的流量根本不进内核 —— 勾了也不会生效。

   程序会自己检测：勾了但内核看不见的软件，右边会标成橙色「没走代理」，
   不会假装成功。看到橙标就开 TUN，或者去那个软件自己的设置里填 127.0.0.1:7897。

3. Windows 10 1903 以上，或 Windows 11。老系统要装 .NET Framework 4.8。


怎么用
------
1. 双击 ProxyPicker.exe。
2. 列表里每个软件右边有一个开关：开 = 走代理，关 = 直连。
3. 改完点右下角「保存并生效」。会弹一句「已生效」，不用重启浏览器。

4. 想先把它收起来：点标题栏右边的「—」。窗口会缩到右下角托盘里，
   代理规则照常生效，再点一下托盘图标就回来了。

   要退出：点标题栏的「×」，或者右键托盘图标 →「退出 ProxyPicker（还原配置）」。
   退出时它会把内核里的规则撤掉，并把 find-process-mode 恢复成原值，
   不会在内核里留下改动。如果你是从 v1.0/v1.1 升级的，旧版还可能往
   客户端 profile 里写过扩展；先跑一次 `--cleanlegacy 清理.txt --yes`
   清掉（会备份），才算真正回到没装过的状态。

顶部那个「出口 日本-B」的小标签，显示的是勾选的软件现在实际走哪个节点，
你在 Clash Verge 里换节点，它十秒内会自己变。


⚠ 先说清楚它会改什么（默认只让点名的软件出网）
------------------------------------------------
第一次运行，默认是「代理白名单」模式。保存之后：

    勾上的软件      → 走代理
    其余所有软件    → 一律直连（跟没开代理一样）

也就是说，装完之后除了你勾的那几个，其他软件不走代理、也不按订阅规则分流；
订阅里那几百条自动分流规则会被兜底 MATCH 挡在后面，暂时不起作用，
访问国外网站会打不开是正常的。想保持原来的上网习惯，请在帮助面板底部
切到「订阅兼容」，再点一次「保存并生效」。

如果你想沿用订阅原来的分流规则：
打开帮助面板（标题栏的「?」），底部有个「模式」按钮，点一下切成
「订阅兼容」，再点一次「保存并生效」。那时候：

    勾上的软件      → 强制走代理组
    其余所有软件    → 按订阅自己的规则走（原来能上的还能上）

注意：这个模式下「取消勾选」不等于直连——只是不再强制走代理，订阅本来
就会代理的软件仍然走代理。想让开关直接控制「走代理 / 直连」，请用
「代理白名单」模式。

订阅原规则逐字保留，订阅自带的段首 MATCH 也原样留着（那是订阅作者写的分流语义，
本工具不会改）。唯一的例外：订阅里一条兜底 MATCH 都没有时，本工具会在规则末尾
补一条 MATCH,DIRECT，否则 mihomo 会拒绝加载这份配置。

    适合：你就是想让这台电脑只有点名的软件能出国，其他一律本地直连。
    不适合：你平时习惯全局挂梯子 —— 切之前先想一下，切完可能觉得网坏了。

两种模式随时能来回切，切完记得点一次「保存并生效」。


第一次运行被 Windows 拦了
-------------------------
会弹「Windows 已保护你的电脑」。因为这个 exe 没有花钱买数字签名，
不是病毒。点「更多信息」→「仍要运行」就行。

如果被 SmartScreen 直接拦下不给运行，右键 exe →「属性」→
最下面勾「解除锁定」→ 确定，再双击。


用腻了怎么撤（重要）
--------------------
这个工具只改 Clash 客户端的规则，不改系统设置，随时能退回原样：

方法一（推荐）：打开 Clash Verge → 「订阅」→ 右键你在用的那个配置
                → 点「更新」或「重新应用」。客户端会重新生成配置，
                  工具插进去的规则就被冲掉了，恢复你原本的分流。

方法二：在 ProxyPicker 里把所有开关都关掉，点保存。
        「代理白名单」模式下这就是「全部直连」——注意不是恢复原样，是全部不走代理；
        「订阅兼容」模式下等于什么都没做，跟你没装过一样。

想彻底删干净，三个地方：
    ProxyPicker.exe 本身              直接删
    %LOCALAPPDATA%\ProxyPicker\       设置、名单、日志、备份
    （从 v1.0/v1.1 升级过才需要）    先跑 --cleanlegacy 清理.txt --yes，
                                      再删客户端 profiles 里遗留的 ProxyPicker 扩展


有个「自己看着」的小功能
------------------------
Clash Verge 换订阅、重启、改设置时会重新生成配置文件，
工具插进去的规则就会被冲掉。以前只有你打开面板它才发现，
现在它自己每 30 秒去问一遍内核：我加的规则还在不在？

- 规则没了 → 自己补回去，屏幕上闪一句「规则被冲掉了，已自动补回」
- 只是少了几个（可能你自己在客户端里删的）→ 只在后台记一笔，不动手
- 连续 3 次补不回来 → 停手，提示你手动点一次「保存并生效」

收进托盘（点「—」）之后它照样在看，所以不用为了这个把窗口开着。

IPv6 归 Clash Verge 自己管，本程序默认一个字都不碰（新版客户端会把外部写的 ipv6
当成越权并弹提示）。如果你在意 IPv6 泄漏，最稳的做法是在客户端设置里关掉 IPv6；
也可以在帮助面板里打开「IPv6 防泄漏」，关掉开关即恢复不管的状态。
代价：关掉 IPv6 后，只支持 IPv6 的网站会连不上（现在几乎没有这种网站）。

它做过的每一次「自动补回 / 放弃 / 失败」都记在
    %LOCALAPPDATA%\ProxyPicker\actions.log
里，一行一次，带时间和原因。觉得它乱动过，翻这个文件就能对账。


支持哪些客户端（实测过的很有限，见下）
--------------------------------------
代码里认这些：Clash Verge Rev / Clash Verge / Clash Nyanpasu /
              Mihomo Party / FlClash / Clash for Windows / 裸 mihomo

但是：**只在 Clash Verge Rev 上真机跑过**。其他客户端是按它们的
      目录结构写的，没在真机上验证，可能会认不出来。
      内核必须要是 mihomo（clash.meta）系，老的 Clash Premium 不行。

认不出来的时候，面板顶部会写「未检测到客户端」，不会乱改你的配置。


出问题想反馈
------------
点标题栏的「?」→「复制诊断信息」，把复制到的东西发给我。
里面写着你用的是哪个客户端、配置在哪、内核版本、规则条数、
名单有没有生效，还有最近 10 条「它自己做过什么」。有这些基本就能定位。
复制前会自动打码：用户名、用户目录、节点名、订阅链接、密码 / 令牌等；
配置路径这类排障必需的信息会保留。


这一版是 v1.3.8（2026-11-12 发布）
------------------------------
这一版只修缺陷。上一版（v1.3.7）新加的两道控制接口保护其实没生效，这次都补上了；
另外修了几处「同一个出口在不同地方算成两种东西」和状态分叉的问题。

· 猜出来的控制端口不再带控制密钥：上一版里判断函数已经说了「别发密钥」，
  但后面的调用代码又无条件把它改回「发」——等于白改。现在只有一处决定这件事，
  并且在真正写请求头的那一行再兜一次底。
· 核对监听进程这一步提到发密钥之前：以前是先把密钥发过去试探、再核对对方身份，
  本机有程序抢占控制端口并回一个「需要认证」就能先拿到密钥。现在任何带密钥的请求
  之前都必须先核对。
· 核对不再只比端口：127.0.0.1:9090 和 127.0.0.2:9090 可能是两个不同程序，
  以前按端口找第一个会认错人。现在连地址一起比。
· 内核退出、别的程序抢到同一端口时，不再沿用「这是内核」的旧结论（会先确认那个进程还在）。
· 另一个 ProxyPicker 窗口（命令行 --restore）执行了还原，正在排队的保存不会再把它推回去：
  以前只看本进程内的计数器，跨进程改动它看不见；现在比对名单文件本身的内容。
· 名单写不进磁盘时，会立刻按磁盘上的原名单把内核退回去，而不是只说一句「看守会恢复」；
  退不回去就明确告诉你「内核和磁盘不一致」，不再含糊。
· 切换分流模式后如果设置写盘失败，内存里的模式会退回原值并保留待保存状态，
  不会在你之后改个排序时把没写成功的模式悄悄存进去。
· 还原时「暂停后台补回」的状态写不进设置文件时，改用单独的小标记文件兜底，
  重启后不会因为残留名单又被接管。
· 流量统计里的 REJECT-DROP 不再被算成「走代理」，和保存校验使用同一套判断。
· 订阅兼容模式下，订阅兜底写成 MATCH,节点选择 时，界面不再误报「未生效」。
· 内核配置接口返回的内容缺少 mode 字段时，按「无法确认」处理，不再当成通过。
· 所有软件都手工指定了策略组时，不再因为一个「没有任何规则在用」的默认组而保存失败。
· 流式写法 rules: ["..."] 括号没闭合时，按配置损坏处理并停止，不再替你猜。
· 备份的原子写降级路径不再「先删旧文件再改名」，中途断电不会把最近一份备份弄丢。
· 自检 217 项全过（通用性 165 + 控制接口安全 41 + 流量对账 11）。
  新增用例里有一条是真起一个假服务、断言它收不到密钥；把修复去掉这条就会变红。

⚠ 已知边界（没变）：同机同用户的程序可以把自己命名成 mihomo.exe，这类冒充挡不住；
  备份目录仍保留订阅的节点密码 / UUID / 订阅地址，请不要把 backup 文件夹发给别人。

上一版是 v1.3.7（2026-11-12 发布）
------------------------------
这一版只修缺陷，不加功能。目标是堵住「界面说成功、实际没代理」和「本机安全边界」两类问题：

· 猜出来的控制端口不再能执行删除：以前只判断「没有请求体」，DELETE /connections
  恰好没有请求体，就被当成只读放行了。现在只允许 GET / HEAD。
· 控制密钥不再乱发：以前探测 /version 失败（超时 / 404 / 500 都算）就会带密钥重试，
  一个有本机端口占用的程序能借此拿到密钥。现在只有明确的 401/403 才重试，并且先按端口
  反查监听进程，确认是 mihomo / Clash 内核才继续。
· 出口校验不再漏 REJECT：以前只拦 DIRECT，策略组切到 REJECT 时勾选软件直接断网，
  界面还显示「已生效」。现在 DIRECT / REJECT / REJECT-DROP 都拦，而且逐个策略组核对，
  不再只看自动选出的那一个。
· 读不到 /configs 不再当成校验通过：内核可能在 global 模式或关掉进程识别，规则根本不生效。
· 出口链路必须追到真节点：链路指向不存在的节点、负载均衡组没有当前选择、循环引用，
  一律按「无法确认」处理，不再拿组名冒充节点。
· 策略组不再「随便挑第一个」：多个组都没有特征、订阅里也没有 MATCH 可循时停止保存并说明原因。
· 合法组名带「冒号 + 空格」时，规则会写成 YAML 引号字符串，不再把配置结构弄坏；
  流式写法 `rules: ["MATCH,..."]` 和 `proxy-groups: [{...}]` 也能正确处理。
· 备份的内容和指纹来自同一次读取：以前先写备份、再重读配置算指纹，
  客户端正好更新订阅时会「备份是旧订阅、指纹是新订阅」，还原时误判为来源一致。
· 保存改成两阶段：名单先完整写到临时文件，写不进去就不推内核；推送成功后再原子替换。
· 一次保存从「旧连接快照」到「定向重连」整段锁住，托盘还原插不进中间；
  等锁期间发生过还原，旧保存任务会作废，不会又把配置推回去。
· 切换分流模式不再立刻写 settings.json：只有保存成功才落盘，避免「切了没保存、
  下次启动模式和内核规则对不上」。只切模式、名单没动时也会重连受影响的软件。
· 顶部出口的周期刷新也跟随实际策略组了（以前十秒后又退回 GLOBAL 显示 DIRECT）。
· 退出还原期间禁止再起保存任务（以前 DoEvents 抽消息泵时还能点保存）。
· 后台看守不再把订阅自带的进程规则误判成「兜底 MATCH 位置错误」，不会每轮无效重推。
· 还原时名单文件删不掉，会暂停自动补回并明确提示，不再「刚还原又被接管」。
· 诊断里的「策略组 · 出口 · GLOBAL」组合行也脱敏了；备份目录权限收紧到当前用户 + 管理员。
· 自检 204 项全过（通用性 158 + 控制接口安全 37 + 流量对账 9）。

⚠ 备份目录里有什么：%LOCALAPPDATA%\ProxyPicker\backup\ 保留了接管前的配置，
  里面有订阅的节点密码 / UUID / 订阅地址（还原需要它们）。本程序不会上传，
  但请不要把整个数据目录或这个 backup 文件夹直接发给别人。

  必须排在勾选规则之后，否则不显示「名单已生效」。
· 名单文件坏了会拦住保存，不会静默变成「全部直连」；旧版清理不再凭文件里
  提到 ProxyPicker 就删文件；退出还原超时会给你「继续运行再试 / 带残留退出」的选择。
· 接管意图核对与模式无关：订阅兼容模式下删掉名单文件即撤销接管，自动补回也会停手；
  识别为「意图已撤销」后不计失败、不弹「请点保存」，记 SKIP 日志。
· 自检 171 项全过（通用性 130 + 控制接口安全 32 + 流量对账 9）。
· 顶部「默认出口」取自默认策略组，不等于每个勾选软件各自的真实链路；
  链路读不出来的流量会标「代理≈」，不当成实测值。
· 例外说明：为修 ChatGPT 等应用的登录，白名单模式下会自动给 msedgewebview2.exe
  加一条代理规则（默认开启）。这个进程被多个 Windows 应用共用，所以未勾选的
  WebView2 应用也可能跟着走代理。不想要它：把 exe 旁边 settings.json 里的
  loginWindowProxy 改成 false，或切到「订阅兼容」（兼容模式不加这条）。

上两版（v1.2.4 / v1.2.3）修的是空名单兜底位置与「别误伤、别留残留」：
· 你自己写在订阅规则最前面、策略叫 PP-FIXED 的进程规则，不会再被当成
  工具的旧规则删掉。现在只删带完整 `# PP-BEGIN / # PP-END` 标记的块。
· 退出还原：不再只看第一条规则；只要内核里任意位置还有本工具的规则就还原。
  读内核失败时按「有」处理，不再因为读不到就跳过还原。find-process-mode
  也会恢复成接管前的值，不再永久留下 always。
· 目录规则边界收紧：`C:\Program Files\bin`、`C:\Users\Public` 这类公共容器
  不再生成整树规则；装在 `Public\App` 里的软件仍然只覆盖它自己的 App 目录。
· 勾 Electron 软件不会再顺手写一条全局 `node.exe` 规则；node / python / java
  这类共用运行时只由目录规则覆盖，不按裸名全局代理。
· 名单里有解析不了的行时，保存会直接停下并告诉你是第几行，不会把那条
  悄悄改成直连。
· 摘要卡「分流异常 N 个」后面会直接跟软件名；帮助面板第一行列出原因和
  下一步，完整列表在「复制诊断信息」里。
· `--scan` 也脱敏了（以前只有 --diag/--api/--raw 脱敏），并把访问域名打码。
· 从 v1.0 / v1.1 升级的用户，可以用 `--cleanlegacy` 清掉旧版写进
  Clash Verge profile 的扩展（先备份，只认 ProxyPicker 标记）。
