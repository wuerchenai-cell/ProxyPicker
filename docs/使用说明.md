ProxyPicker 使用说明
====================

下载最新版 / 反馈问题：https://github.com/wuerchenai-cell/ProxyPicker
（程序帮助面板里点版本号也能跳过去）

这是什么
--------
一个托盘小工具：只让「你勾选的软件」走代理，其余软件怎么走由你选的模式决定。
改完点保存，只重连这次改到的软件，其他连接不会断，也不用重启浏览器。

分流模式（帮助面板底部那个按钮，随时能切）
  · 代理白名单（新机器默认）：勾的走代理，其余一律直连，跟没开代理一样。
    订阅里那几百条分流规则会被一条兜底规则挡在后面，暂时不起作用。
    这是刻意的产品定位（只让需要外网的软件走代理），第一次用容易懵 ——
    发现某个软件上不了网，先回来看看它有没有勾上。
  · 订阅兼容（老配置保持）：勾的走代理，其余完全按订阅原规则走。
    上网习惯一点不变，只是在规则最前面插了几行。想沿用订阅分流的选这个。
    已有 settings.json 且没写过 mode 的老用户，升级后仍保持这个模式，不会被悄悄改掉。
切完必须点一次「保存并生效」才会真正改到内核；保存前看守不会替你应用新模式。


怎么用
------
1. 双击 exe，右下角出现图标，面板自动弹出。
2. 点一行 = 开/关。开 = 走代理，关 = 直连。
3. 点右下角「保存并生效」。底部会告诉这次重连了几个软件、清掉几条旧连接。
4. 标题栏右边「—」= 收进托盘（继续后台看守）；「×」= 直接退出程序，
   并且会把内核里的规则一起撤掉，电脑回到没开这个软件的状态。
   想后台看守就用「—」，想彻底结束就用「×」或托盘右键 →「退出」。


四个标签
--------
常用    高频软件 + 已勾选的软件
已选    核对当前代理名单
运行中  此刻正在跑的软件
全部    所有已安装软件（标签上带总数）。以后新装的软件，下次打开会自动出现

「常用」只是过滤视图：一个软件如果「非常用 + 没勾 + 没运行」，在常用 / 已选 /
运行中三个标签里都看不到，切到「全部」或在搜索框输名字就能找到。
绿色版、MSIX、游戏目录、脚本类程序可能不在自动扫描范围内：托盘右键 →
「手动添加软件…」手选 exe，加过一次会一直留在列表里（副标题标「手工添加」）。


排序
----
· 按住任意一行上下拖动，就能改顺序。
· 点标签右侧的按钮，可以切回「智能」（按勾选习惯自动排）、「手动」或「按名称」。
· 排序和习惯存在 settings.json 里，下次打开还在。


右键一行
--------
改为直连 / 只代理这一个 / 打开文件位置 / 复制进程名 / 在列表中隐藏


实时网速
--------
摘要卡右侧是两条通道的实时速率：
  代理 = 勾选软件走代理的流量
  直连 = 其余软件直接连的流量
下面那条折线是最近 30 秒的走势（每秒一个点，横轴固定、纵轴固定）。
曲线只会整体向左平移，已经画过去的高度不会因为后来网速变快变慢而重新缩放——
所以看到的起伏都是当时真实的网速，不会「自己上下动」。
数据来自本机内核的连接表。


换节点（重要）
--------------
摘要卡第三行那个浅蓝胶囊，写的是「勾选的软件现在实际走哪个节点」——
它追的是真实链路末端，不是 Clash 界面上的全局选择。

换节点就在 Clash Verge 里换（切「🚀 节点选择」组）。换完 10 秒内：
  · 胶囊自动变成新节点名
  · 弹出「出口已切到 xxx」的提示
不用点刷新，也不用重启软件。

想让勾选的软件单独钉死一个节点（不跟主组走）：
在 Clash Verge 的 PP-FIXED 组里直接选具体节点即可。
选「🚀 节点选择」是跟随，选「♻️ 自动选择」是跟着测速漂移。


关于 IPv6
---------
IPv6 由 Clash Verge 这类客户端自己的设置接管，ProxyPicker 默认一个字都不碰。

原因：新版客户端把 ipv6 列为「应用设置接管」字段，写在 Merge / Script 扩展里、
或由外部程序推送，都会被丢弃并弹出「这些值已被丢弃」的橙色提示。

如果你在意 IPv6 泄漏（TUN 的 IPv6 是内网段，Windows 不会拿它当访问公网的源地址，
流量可能从物理网卡直出、绕过代理）：请直接在 Clash Verge 设置界面里关闭 IPv6，
那里才是唯一稳定生效的地方。也可以在 ProxyPicker 帮助面板里打开「IPv6 防泄漏」，
程序保存时会写入 ipv6: false 并回读确认；客户端重新生成配置时可能覆盖它。
关掉开关后程序不再改动这个字段，原来的设置自然恢复。


版本与更新
----------
点标题栏的「?」，面板右上角会显示当前版本，例如 v1.3.4。

程序一启动就自动查一次新版本，不用记得去点：不管面板开没开、是不是开机自启
后台运行，到点都会向 GitHub 发一次 GET。查到比本机新的版本时，托盘会弹一条
系统通知，面板右上角的版本号同时变成「v1.3.4 → v1.4.0 去下载」；
点通知打开面板，点版本号打开该版本的 Release 页面，自己下载替换。
程序不会自动下载、不会改自己 —— 这个 exe 只有自签名证书，Windows 不认识
发布者，「自己下载自己覆盖自己」最容易被 Defender / SmartScreen 当成恶意软件。

同一个版本每次运行只提醒一次。每天最多联网查一次（上次没连上则 4 小时后重试）；
即使当天不再联网，只要上次已经查到过新版，下次启动仍会用缓存再提醒一次，
不会因为「没打开面板」或「刚好在节流期」就错过。托盘里的「检查更新」可随时手动复查。

连不上 GitHub（没开代理）时安静收场，不弹窗不打扰。
不想要这个功能：把 settings.json 里的 "updateCheck" 改成 false。
注意「完全接管」模式下，程序会给自己单独放行一条规则，否则这个 GET 会被
MATCH,DIRECT 直连送出去、根本连不上；关掉 updateCheck 这条规则也会一起消失。


带辅助进程的软件（Antigravity / VS Code / Electron 类）
--------------------------------------------------------
这类软件真正发登录、更新请求的，往往不是你能点开的那个主程序，而是安装目录
深处的另一个 exe（Antigravity 是 resources\bin\language_server.exe）。
只按进程名勾选，这些请求会落到「直连」，表现就是登录转圈、一直失败。

ProxyPicker 的处理方式是「按安装目录整体覆盖」：
  勾一个软件时，自动为它自己的安装目录写一条路径规则，
  这个目录下**现在和以后**出现的所有程序都一起走代理。
  · 不需要你去找是哪个 helper 在联网，也不用反复试
  · 软件更新后新增的程序自动包含，不用重新设置
  · 换台电脑、换个软件同样成立，不是只对 Antigravity 特判
  · 只认软件自己的目录：Program Files、AppData、桌面、下载这些公共容器
    本身不生成规则；容器下面某个软件自己的子目录（如 Public\App）仍会覆盖，
    避免把无关软件一起代理走
  · 极老的、不认识路径规则的内核会自动退回「只按进程名」并提示，
    不会因此保存失败


换电脑
------
整个 exe 拷过去就能用，不需要安装。默认不写注册表；唯一例外是你在设置里
主动打开「开机自启」，这时才会在 HKCU\Software\Microsoft\Windows\CurrentVersion\Run
写一条启动记录，关掉即删除。程序会自动识别这些客户端：
  Clash Verge Rev / Clash Verge / Clash Nyanpasu / Mihomo Party / FlClash /
  Clash for Windows / 裸 mihomo

想把手感一起带走：把 settings.json 放在 exe 旁边（绿色模式），
排序、使用次数、隐藏项都会跟着走。


分享给别人
----------
直接发 `分享包\ProxyPicker-v1.3.3-share.zip`（本地包名 `ProxyPicker-分享版.zip`，约 154 KB）就行，
里面是 exe + 一份「说明-先看这个.txt」，
那份说明是按「完全不懂的人」写的，把前提条件、会被 Windows 拦、怎么撤销都写进去了。

发之前你要知道五件事：
1. 对方电脑上必须本来就有 Clash Verge 之类的客户端，并且**建议开着 TUN**。
   不开 TUN 也能跑，但只有「读系统代理」的软件受控，其余软件会被标成
   橙色「没走代理」—— 那不是故障，是它压根没把流量交给内核。
   这工具不带代理，它只是分配谁走代理。
2. 对方那边没有 PP-FIXED 这个组，程序会自动挑「🚀 节点选择」这类组，
   已经用一份「删掉 PP-FIXED」的配置试跑过，选组是正确的。
3. 对方第一次打开默认是「代理白名单」：没勾的软件一律直连，不再按订阅规则走 ——
   这是和老机器订阅兼容模式最大的不同，用之前先讲清楚，免得以为网坏了。
   判断依据是有没有 settings.json：没有就是新机器，走代理白名单；
   已有配置且没写过 mode 字段的老用户保持订阅兼容，升级不会偷偷改模式。
4. 真机只在 Clash Verge Rev 上验证过；其它客户端是按目录结构写的，没实测。
5. 装了多个 Clash 系客户端（Verge + Party 之类）时，现在会自动选「正在用的那个」：
   优先认正在运行的内核命令行指向的目录，其次客户端进程、控制端口、配置更新时间。
   跑 `ProxyPicker.exe --diag 诊断.txt`，能看到每个候选的得分和最后选中的原因。
   如果两个客户端同时在跑，自动选择仍可能拿不准，建议只留一个在运行；
   没运行但配置文件更新的客户端，不会压过正在运行的那个。
   识别结果有 5 秒缓存：切换客户端或订阅后，等几秒再点「保存并生效」最稳妥；
   一次保存内部的原值捕获、策略组计算、推送、回读、旧连接快照与定向重连
   都锁定同一份配置；但 --raw / --diag 这类单独敲的调试命令仍会自己重新识别一次。


退出时会做什么（重要）
----------------------
点「×」或托盘「退出」：先把内核里插进去的规则撤掉、把 IPv6 和
find-process-mode 恢复成接管前的值，再结束进程。换句话说，不用它的时候，
内核里不残留这个软件的任何改动。
勾选名单和设置留在本机（下次打开还是上次的选择），它们不改变系统行为。

如果你是从 v1.0 / v1.1 升级上来的，老版本还可能往 Clash Verge 的
profile 扩展里写过规则。这个不会随内核还原自动消失，需要单独清一次：
  ProxyPicker.exe --cleanlegacy 清理结果.txt          （只检测，不改文件）
  ProxyPicker.exe --cleanlegacy 清理结果.txt --yes    （备份后清理）
它只处理能完整识别为旧版 ProxyPicker 生成的扩展结构；只提到工具名称、
但认不出旧版结构的文件不会被删，也不会列入清理结果。清理前会整份备份到
%LOCALAPPDATA%\ProxyPicker\backup\legacy-时间\。清完请重启一次客户端。

怎么撤掉（回到原本的分流）
--------------------------
方法一（推荐）：直接退出程序 —— 现在退出就会把规则撤掉。
方法二（只暂时有效）：Clash Verge →「订阅」→ 右键在用的配置 →「更新」或重新应用；
        客户端重新生成配置时会把工具插的规则冲掉，但只要本程序还在运行、
        接管名单还在，后台看守随后又会把规则补回来。彻底撤销请用方法一。
彻底删干净：先退出程序；如果从 v1.0 / v1.1 升级过，先跑一次
            --cleanlegacy 清理结果.txt --yes；
            再删掉 exe、%LOCALAPPDATA%\ProxyPicker\、
            以及开机启动项（HKCU\Software\Microsoft\Windows\CurrentVersion\Run 里的 ProxyPicker）。
            如果从很老的版本升级过，客户端的 pp_rules 目录也可能有残留（新版本不写它）。


规则被客户端冲掉了会怎样
------------------------
换订阅、重启 Verge、改设置都会重新生成配置，把插进去的规则冲掉。

现在它自己每 30 秒核对一次（收进托盘也不停）：发现「名单非空但规则没了」
就自己补回去，屏幕上闪一句「规则被冲掉了，已自动补回」。只少几个的那种
半丢状态只记账、不动手，免得把你自己在客户端里的调整抹掉。
连续 3 次补不回来会停手并提示手动保存，不会无限重试。

它做过的每一次补回 / 失败都记在 %LOCALAPPDATA%\ProxyPicker\actions.log。
实测：637 条规则被冲掉 → 托盘里放着不动 → 33 秒后自己补成 647 条。
（早期版本还会顺手关 IPv6；现在 IPv6 归客户端管，默认不碰，只有主动开启防泄漏时才管。）


分流异常怎么看
--------------
摘要卡写「分流异常 N 个」时，后面会直接跟上前两个软件名；点「?」，
帮助面板第一行会列出是哪个 exe、预期什么、实际多少条连接走了哪边、
下一步该做什么；点摘要里的「分流异常 N 个」也能看完整清单。

v1.3.1 起这个数只算「本次规则生效后才建立的连接」：之前建立、
仍挂着不关的浏览器长连接不会重匹配规则，已从对账里排除；程序自动放行的
辅助进程（登录窗口、同目录 helper、程序自身）也按「走代理」计入预期，
不会再自己放行、自己报警。诊断信息里会写明排除了几条旧连接。


出问题怎么办
------------
点标题栏的「?」→「复制诊断信息」，里面写着识别到的客户端、配置路径、
内核版本、规则条数、名单是否生效，最后附最近 10 条「它自己做过什么」。
把这些贴出来就能定位问题。

命令行也能用（每个开关都必须带输出文件）。会改动状态的有三类：
  --apply / --cleanlegacy --yes 会改动磁盘配置或名单；
  --restore 不写磁盘订阅，但会向运行中的内核推送配置（不是只读命令）。
其余开关不改任何配置：
  ProxyPicker.exe --diag 诊断.txt
  ProxyPicker.exe --audit 对账.txt      名单 vs 内核，逐条列出差异
  ProxyPicker.exe --selftest 自检.txt
  ProxyPicker.exe --api 输出.txt /proxies      直接问内核要原始数据
  ProxyPicker.exe --raw 输出.txt GET /rules    连响应头一起打出来，排查用（非 GET 要加 --yes）
  ProxyPicker.exe --cleanlegacy 清理.txt        检查旧版写进客户端 profile 的扩展
  ProxyPicker.exe --cleanlegacy 清理.txt --yes  备份后清理（升级/卸载前用）
  ProxyPicker.exe --version 版本.txt           版本号 + 版本比较自检
  ProxyPicker.exe --checkupdate 更新.txt        查一次 GitHub 上的最新版本
  ProxyPicker.exe --apply 结果.txt --yes       唯一会真实改分流；必须加 --yes，失败退出码非 0
                                              没有勾选名单时会被拒绝，请先在界面保存一次
  ProxyPicker.exe --restore 结果.txt          撤掉内核里本工具写的规则（等同退出时的还原），不动订阅和名单
  托盘右键 →「还原上次保存前的配置」= 清除内核里本工具的规则 + 撤销接管状态（删勾选名单），
  看守不会再自动接管；只有「备份来源路径」和「备份时配置内容指纹」都与当前一致时才整份推回备份，
  对不上（含 Clash Verge 在同一路径换订阅）就改为按当前订阅重建干净配置，重建失败则停止并提示。

以上输出都会先脱敏：用户名、用户目录、节点名（--diag 里）、机器标识与
UUID / 管道实例 ID、--api/--raw 里的访问域名，以及 password / token / secret /
authorization 等敏感字段都会打码。--diag / --audit / --list / --selftest / --pipes
可以贴给能帮你的人；--api / --raw 是原始接口响应，属于敏感资料，只发给你信任的人，
不要在公开场合全文贴出（脱敏不能当作无条件保证）。
--pipes 只列内核相关的管道（mihomo / clash 系），不列系统里那六百多个无关管道。
